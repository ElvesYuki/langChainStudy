# Agent 工程化系统学习总纲：课程与 PEF 项目映射

## 1. 学习目标

本总纲服务于具备 7 年 Java 开发经验、具备架构设计能力、已通过 AI 辅助完成 PEF Agent 平台，但对
模型调用和 Agent 关键代码独立编码经验相对不足的学习者。

目标不是记住 LangChain 或 LangGraph API，而是形成四层能力：

```text
模型协议层
  messages / tools / tool_choice / content / tool_calls

Agent 运行层
  context / loop / routing / tool / delegation / streaming

可靠执行层
  execution / attempt / idempotency / lease / recovery / action

平台治理层
  permission / secret / release / evaluation / promotion / SLO
```

完成总纲后，应能够：

- 独立解释一次 Agent 请求从 Conversation 到最终回答的完整链路。
- 阅读并修改 Model、Runtime、Tool、Context、Execution 的关键代码。
- 区分 LangGraph 调度状态、Checkpoint 和数据库权威业务事实。
- 设计 Provider 超时、取消、截断、结果未知和重放边界。
- 设计 Tool 权限、副作用、幂等、确认和 Prompt Injection 防线。
- 解释主/子 Agent、MCP、Skills、A2A、Memory 和 RAG 的责任边界。
- 使用 Dataset、Evaluation、Candidate 和 Promotion Gate 管理质量。
- 判断教学 Demo、业务应用和生产级 Agent 平台之间的差距。

## 2. 学习方法与完成标准

### 2.1 单点讲解模板

后续每个编号按以下顺序展开：

1. `Why`：为什么需要它，缺失时会发生什么。
2. `What`：核心概念、协议和状态。
3. `How`：最小实现与框架实现。
4. `PEF`：项目真实代码入口和调用链。
5. `Failure`：超时、取消、崩溃、并发、重复和 unknown。
6. `Security`：身份、权限、Secret、数据隔离和注入风险。
7. `Verify`：测试、观测、评测和自测题。

### 2.2 掌握深度

每个知识点可独立选择深度：

| 等级 | 掌握标准 |
|---|---|
| D1 了解 | 能不用框架术语堆砌，准确解释作用和边界 |
| D2 读码 | 能从入口跟踪到核心分支，说明输入、输出和状态变化 |
| D3 编码 | 能独立写最小实现、失败用例和回归测试 |
| D4 架构 | 能定义权威事实、幂等、恢复、安全和演进协议 |

### 2.3 学习状态

状态由后续学习记录维护：`未开始 / 学习中 / 已复述 / 已练习 / 已掌握`。课程视频看完不自动等于掌握。

# 第一部分：模型与 Agent 基础

## 第 1 章 大模型 Agent 开发基础

### 章节目标

理解模型为什么能生成内容、应用如何调用模型、Function Calling 如何转化为 Agent 循环，并能手写一个
不依赖框架的最小 Tool Calling Agent。

### 知识点

- `AGL-01-01`（1-2～1-6）模型生命周期：预训练、监督微调、偏好对齐、强化学习、推理模型与普通生成模型。
  - 深度建议：D1。
  - 重点：训练方式如何影响能力、延迟、上下文、稳定性和成本，而不是学习训练算法。
  - 已迁入讲解：[AGL-01-01 模型生命周期 D1 讲解](topics/AGL-01-01-模型生命周期-D1讲解.md)。
- `AGL-01-02`（1-7～1-10）模型 API 请求：endpoint、鉴权、model、messages、temperature、max tokens、stream。
  - 深度建议：D3。
  - PEF：`provider/litellm_provider.py`、`runtime/model_invoker.py`。
- `AGL-01-03`（1-7～1-10）消息协议：system、user、assistant、tool，以及多模态内容块和消息顺序。
  - 深度建议：D3。
  - PEF：`runtime/protocol/messages.py`、`runtime/message_adapter.py`。
- `AGL-01-04`（1-7～1-10）同步、流式与最终结果：首块前失败、首块后失败、finish reason、usage 和 provider request ID。
  - 深度建议：D4。
  - PEF：`runtime/model_invoker.py`、`gateway/sse.py`、`runtime/protocol/events.py`。
- `AGL-01-05`（1-11～1-14）Function Calling 请求：tools、JSON Schema、tool_choice、并行 ToolCall。
  - 深度建议：D3。
  - PEF：`runtime/protocol/tools.py`、`registry/tool_definition_service.py`。
- `AGL-01-06`（1-11～1-14）Function Calling 响应：content、tool_calls、call ID、arguments 和 ToolResult 回填。
  - 深度建议：D4。
  - PEF：`runtime/protocol/model.py`、`runtime/tool_runtime.py`。
- `AGL-01-07`（1-11～1-14）结构化输出异常：JSON 截断、Schema 不合法、重复 call ID、未知 Tool 和空 content。
  - 深度建议：D4。
  - PEF：`runtime/runtime_loop.py`、`runtime/tool_runtime.py`。
- `AGL-01-08`（1-15～1-17）Agent 的本质：模型决策、环境执行、结果观察和终止条件。
  - 深度建议：D2。
- `AGL-01-09`（1-18～1-20）手写 ReAct：Prompt 文本协议与原生结构化 Tool Calling 的差异。
  - 深度建议：D3。
  - 练习：不使用 LangChain 写一个有最大步数、Tool Schema 和错误终止的 Agent Loop。
- `AGL-01-10`（1-18～1-20）Agent 循环控制：最大步数、Token 预算、重复调用、无进展检测和最终回答。
  - 深度建议：D4。
  - PEF：`runtime/runtime_loop.py`、`runtime/agent_runtime.py`。
- `AGL-01-11`（1-21～1-23）客服案例拆解：Prompt、知识查询、业务查询、回答和部署边界。
  - 深度建议：D2。
- `AGL-01-12`（课程外生产补充）Provider 超时、取消、重试和 unknown 的分类。
  - 深度建议：D4。
  - PEF：`runtime/model_invoker.py`、`runtime/cancellation.py`、`execution/execution_fact_service.py`。

### 本章完成标准

- 能画出 `messages + tools -> model -> tool_calls -> ToolResult -> model` 链路。
- 能解释模型为什么只拥有调用意图，不拥有 Tool 权限。
- 能说明 ToolCall 截断和 Provider 结果未知为什么不能简单重试。

## 第 2 章 大模型私有化部署方案（上）

- `AGL-02-03`（2-4）单机多 GPU 与“负载均衡、模型并行、请求并发”的区别。
- `AGL-02-04`（2-6～2-11）vLLM：PagedAttention、Continuous Batching、KV Cache、并发和 OpenAI-compatible API。
- `AGL-02-05`（2-8～2-11）离线推理与在线服务的参数、生命周期和容量差异。
- `AGL-02-06`（2-12～2-15）生产部署：健康检查、并发限制、超时、模型预热、滚动更新和推理模型支持。
