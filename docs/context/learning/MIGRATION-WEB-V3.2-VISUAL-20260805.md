# 培训网站 V3.2 演讲视觉改版说明

## 1. 调整原因

V3.1 的内容已经恢复并增强，但大多数页面仍使用“页眉 + 多张圆角卡片 + 底部总结条”的统一结构。代码虽然整齐，演讲却呈现出后台仪表盘感，不同内容缺少不同的视觉语言。

V3.2 保留 22 页内容、阅读文章、导航、备注和渐进展示，只重做演讲页面的主体构图。

## 2. 设计原则

- 模块化用于代码维护，不等于视觉必须套同一模板；
- 每页先识别内容关系，再选择空间结构；
- 卡片仅用于真正的分类或对比；
- 流程使用时间线、轨道和连接关系；
- 状态使用看板，职责使用泳道，失败使用分支；
- 保持统一字体、色彩和留白，同时允许每页拥有独立构图；
- 渐进展示按讲解语义分组，不机械地逐元素出现。

## 3. 主要视觉形式

- 贯穿案例：文件工作台与验收产物；
- 普通对话与智能体：双时间线；
- AI 应用：四层剖面；
- 五概念：交互式概念浏览器；
- 上下文：读取管道与信息漏斗；
- 大模型：输入—生成—输出舞台与能力四象限；
- 工具：围绕外部对象的动作轨道与调用控制台；
- 智能体：目标—状态—循环三角、任务看板和环形循环；
- 概念关系：AI 应用容器中的嵌套关系；
- 职责边界：四角色泳道；
- 完整链路：带证据节点的时间线；
- 失败场景：正常流程旁的异常分支；
- 任务定义：模糊请求与结构化任务单；
- 部门场景：输入—产出矩阵；
- 结尾：判断面板与完整责任链。

## 4. 代码组织

- `slides.tsx` 只负责 22 页顺序、标题、备注和页面组合；
- `chapter-visuals.tsx` 保存本章专属视觉构图；
- `presentation/` 继续负责全屏、导航、渐进步骤和演讲者备注；
- 通用 shadcn/ui 不主导幻灯片视觉。
